# ADR-024 — Locate me with fake positions before the Geolocation API

**Date**: 2026-11-15
**Status**: accepted

## Context

The previous app had a button that centred the map on the visitor and marked them with a blue dot. It called the browser's Geolocation API directly from screen code: a first request in high accuracy, a second in low accuracy after a timeout, a watch that kept the dot moving, a compass, follow and heading modes, and messages that changed with the browser, the platform and the permission state. None of it was behind a port, and none of it was tested.

The rebuilt `locate-me` ability needs the button, the dot, the camera move and the failure messages first. A real adapter needs decisions this change does not make yet: high or low accuracy, single reading or watch, timeouts, when to ask for permission, and how to say on the "Who sees what" page that the browser's location provider sees the visitor ([ADR-021](ADR-021-maplibre-and-the-openfreemap-basemap.md)).

## Decision

- The domain of `locate-me` defines the port `Locate`, a function returning an observable of `LocateResult`: either a located position or a failure value, `permission-denied` or `position-unavailable`. Failures are values, not errors, so the use case maps each one to a status the page shows. The use case turns each request into `locating`, then into a view centred on the position at zoom 16, or into the failure.
- For now, the only adapter is in memory: `implementation/in-memory/in-memory-locate.ts` answers with a result it is given. The result is a fake position within 3 km of the centre of Paris, generated by `implementation/in-memory/fake-position.ts` with Faker's `SimpleFaker` and a fixed seed, so that it is the same at every build.
- Faker runs at build time only. The home route's `+page.server.ts` loads the fake position; the route is prerendered, so SvelteKit writes the position into the page and its `__data.json`, and the browser receives data, never Faker. dependency-cruiser already allows `@faker-js/faker` in in-memory adapters only ([ADR-020](ADR-020-map-glyphs-generated-at-build.md)), and the build is checked to contain no Faker code.
- The map draws the position through an overlay: `show-map`'s map component accepts overlays, functions from the MapLibre map to an observable that draws while subscribed and removes its drawing when unsubscribed. `locate-me` provides the overlay that places the dot and flies to the position; the route passes it to the map, so neither ability imports the other ([ADR-008](ADR-008-composition-in-routes.md)).
- The dot is the previous app's: 18 px, blue with a white border and a faint halo, without accuracy circle, which the previous app did not draw. It is an image named "Your position".

## Replacing it with the Geolocation API

A `browser` adapter in `implementation/browser/` will implement `Locate` with `navigator.geolocation.getCurrentPosition`, mapping `PERMISSION_DENIED` to `permission-denied`, `POSITION_UNAVAILABLE` and `TIMEOUT` to `position-unavailable`, and a missing API or an insecure context to `position-unavailable` too. The route will pass it instead of the in-memory adapter, `+page.server.ts` and `fake-position.ts` will go, and the in-memory adapter will stay for the tests and the Cucumber scenarios. The same change will add the browser's location provider to the "Who sees what" page. The use case, the overlay and the button do not change.

## Consequences

- The button works without asking for permission, and the end-to-end and Lighthouse runs need no geolocation emulation.
- Every visitor is placed at the same spot near the Louvre until the real adapter lands: the feature is a demonstration, not a service.
- The previous app's watch, compass, follow and heading modes, and its platform-specific messages, are left out; each will be an ability or a change of its own.

## Alternatives considered

- **The Geolocation API right away**: the owner chose to settle the ability's shape first, with data that does not depend on a permission prompt.
- **Faker in the browser**: its code would weigh on the map pages, already near their script budget ([ADR-022](ADR-022-lighthouse-budgets-per-page.md)), for data that never changes.
- **A fixed position written by hand**: nothing to generate, but dependency-cruiser already reserves Faker for in-memory adapters, and a seeded generator grows with the fake data the next abilities need.
- **A marker or camera prop on the map component**: each ability drawing on the map would add a prop to `show-map`; overlays keep the map component unaware of what is drawn on it.
